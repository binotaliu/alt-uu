# Shell patch audit (Step 7)

Baseline: `nativephp/mobile` 4.5.2. Method: each patch's intent was re-derived from its `.diff` and the current upstream file (not diffed blindly against an old snapshot, see the stale-snapshot pitfall in the upgrade notes). "Native" means the shell renders a SuperNative tree, so the shell WebView, `PHPSchemeHandler` and `PHPWebViewClient` are not in play.

**Status.** The cutover is done: `NATIVEPHP_START_URL` defaults to `/courses` (a native route) and the Vue SPA, the material proxy and the `X-Native-Fetch` handoff are deleted, so nothing depends on the removed WebView patches. Device builds of the native UI have not been run by the agents; the Swift/Kotlin edits below were never compiled here.

## media-player plugin (overlay removed)

Removed: `MediaPlayer.SetPlayer` (iOS class, Android class, manifest entry, JS export), iOS `MediaPlayerState.swift` (state + `MediaPlayerOverlayHost`), Android `MediaPlayerState` object + `MediaPlayerOverlayHost` composable, the `publishOverlay` / `overlayPublishing` plumbing, iOS `MediaPlayerData` and `NativeMediaPlayerView.init(data:)`.

Kept on purpose: `MediaPlayerFrame` (still a parameter of `setPlayer` and part of the Android `GetState` payload, so no blind signature refactor), the `force` rebuild flag, `MediaPlayerData` on Android (the renderer composes it), and `AppAccent.SetColor` + `AccentPalette`: `App\Services\NativeAccent::apply()` calls it through `MediaPlayer::setAccent()` so the iOS window tint follows the accent, which mobile-ui's theme push does not do (`NativeMediaPlayerView` also still falls back to `AccentPalette` without `usesNativeTheme`). `ThemeTest` asserts the call.

None of the Swift/Kotlin edits could be compiled here. Verify with a real build.

## Open questions

1. Android PiP: `MediaPlayerRenderer` never passes `isInPiP` (it only came from the removed `MainActivity` hook), so the PiP window shows the full controls. Cosmetic. Plumb PiP state in-plugin if wanted.
2. The iOS single-window pbxproj enforcement is kept (decided: keep; it is unrelated to the WebView).
3. Forwarding the school cookies to `native:html-view` and the media player (cookie-protected images and WebVTT) remains a known gap (conventions 11.5 / 11.7); the removed `materialFetchHandoff` was the only place that assembled UA + cookie headers, so a plugin-side implementation has to rebuild that.
