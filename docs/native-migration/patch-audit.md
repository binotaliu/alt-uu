# Shell patch audit (Step 7)

Baseline: `nativephp/mobile` 4.5.2. Method: each patch's intent was re-derived from its `.diff` and the current upstream file (not diffed blindly against an old snapshot, see the stale-snapshot pitfall in the upgrade notes). "Native" means the shell renders a SuperNative tree, so the shell WebView, `PHPSchemeHandler` and `PHPWebViewClient` are not in play.

**Release gate.** `NATIVEPHP_START_URL` is still `/` (the Vue SPA) until the Step 8 cutover. The Vue app still calls `MediaPlayer.SetPlayer` and relies on the base64 body decode, the iOS safe-area CSS variables and the Android back-press event. Do not build or release `main` between this step and Step 8.

## media-player plugin (legacy overlay)

Removed: `MediaPlayer.SetPlayer` (iOS class, Android class, manifest entry, JS export), iOS `MediaPlayerState.swift` (state + `MediaPlayerOverlayHost`), Android `MediaPlayerState` object + `MediaPlayerOverlayHost` composable, the `publishOverlay` / `overlayPublishing` plumbing, iOS `MediaPlayerData` and `NativeMediaPlayerView.init(data:)`.

Kept on purpose: `MediaPlayerFrame` (still a parameter of `setPlayer` and part of the Android `GetState` payload, so no blind signature refactor), the `force` rebuild flag, `MediaPlayerData` on Android (the renderer composes it), `AppAccent.SetColor` + `AccentPalette` (sets the iOS window tint, which mobile-ui's theme push does not; `NativeMediaPlayerView` still falls back to `AccentPalette` without `usesNativeTheme`). Nothing native or PHP calls `AppAccent.SetColor`; only `resources/js/lib/nativeAccent.ts` does, so it is dead after cutover unless the tint is wanted (open question 3).

None of the Swift/Kotlin edits could be compiled here. Verify with a real build.

## Open questions

1. Android PiP: `MediaPlayerRenderer` never passes `isInPiP` (it only came from the removed `MainActivity` hook), so the PiP window shows the full controls. Cosmetic. Plumb PiP state in-plugin if wanted.
2. Is the iOS single-window pbxproj enforcement still wanted (iPad multitasking)? Kept because it is unrelated to the WebView.
3. Keep `AppAccent.SetColor` for the iOS window tint (then call it from `NativeAccent::apply`), or drop it with `AccentPalette`?
4. Step 8 follow-ups: `resources/js/lib/nativeMediaPlayer.ts` and `nativeAccent.ts` call the removed/legacy bridge functions; delete the material-proxy controller, route, config key and its tests once `ParseMaterialContent` stops emitting proxy URLs.
