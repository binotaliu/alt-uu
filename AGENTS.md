# Alt UU

Alt UU is an unofficial iOS / Android app for NOU (National Open University) students: courses, materials (HTML, video, audio, PDFs), discussion boards, live sessions, school calendar, grades and exam info. It talks to HUNGU (`uu.nou.edu.tw`, AES-encrypted xmlapi), the school portal (HTML scraping), nou-tools, alt-uu-plus (IAP verification and moderation) and the statics worker.

The app is **React Native + Expo (SDK 58, expo-router, NativeWind)** in an npm-workspaces monorepo. It replaced a Laravel + Vue + NativePHP app and ships under the same bundle IDs (iOS `org.binota.alt-uu`, Android `org.binota.alt_uu`) as an in-place update. Web is not a target. TV (react-native-tvos) and desktop apps may be added later as extra `apps/*` that reuse the packages.

## Repository layout

```
apps/mobile/                 Expo app: app.config.ts, expo-router routes (src/app), composition root, platform adapters, fastlane, Maestro e2e
packages/core/               @altuu/core: pure TypeScript. HTTP transport + cookie jar, HUNGU / school portal clients, session
                             authenticators, domain services, drizzle schema + migrations, typed errors, legacy data migration
packages/features/           @altuu/features: screens + hooks (TanStack Query over core services, Zustand client state), app shell
packages/ui/                 @altuu/ui: NativeWind preset (design tokens, accent palettes), base components, Heroicons set
modules/attachment-bridge/   @altuu/attachment-bridge: local Expo module (Swift + Kotlin), the only custom native code
tools/legacy-fixtures-gen/   scripts that generated the parity fixtures from the legacy PHP app
.github/                     lint / tests workflows, mobile-release workflow + setup-expo-build action
```

`apps/mobile/ios` and `apps/mobile/android` are generated by `expo prebuild` and git-ignored. Configure native projects through `app.config.ts` and config plugins only.

## Packages and their rules

### `@altuu/core` (pure TS)

- No React, React Native or Expo imports. ESLint (`no-restricted-imports`) enforces this. Platform services (SQLite driver, secure storage, fetch, clock, random, device info, logger) are **injected** through the interfaces in `packages/core/src/platform`; the app provides them in `apps/mobile/src/platform`. Session contracts live in `src/session/types.ts`.
- `src/http`: `HttpTransport` with an **explicit per-account cookie jar** (Set-Cookie merged per request, redirects followed in JS). Read `src/http/README.md` before touching networking. The app's `Fetch` is `expo/fetch` with `credentials: 'omit'` so native cookie stores never leak between accounts.
- `src/hungu`, `src/school-portal`: protocol clients (`UUCrypto` is a byte-exact port checked against PHP vectors), `HunguSessionAuthenticator` with remembered re-login, reviewer → staging switch, typed errors (`SessionInvalidError { failedAccountId }`, `ExternalServiceUnavailableError`).
- `src/db`: drizzle schema, generated migrations (`npm run db:generate -w @altuu/core`), `CacheRepository` (Laravel-like `remember` / `put` / `forget` with TTL) and `KeyValueStoreRepository`. Credentials and sessions are AES-encrypted with a key held in secure storage.
- `src/accounts`: `createStorageServices` (account manager, active profile, credentials and session stores).
- `src/domains/<domain>/`: one folder per legacy `src/Domains/*` domain, each with an `index.ts` and a `create<Domain>Services(deps)` factory. Conventions:
  - Each legacy Action becomes a function or small class with explicit injected deps. No globals, no singletons.
  - "Endpoints" no longer exist: the service method the UI calls includes the legacy controller logic (validation, composition, error mapping).
  - Return types mirror the legacy ViewModels / DTOs with the same camelCase field names (`<domain>/types.ts`), so screens keep parity.
  - Caching uses the legacy keys and TTLs, prefixed with the account id where legacy scoped per account.
  - Cross-domain needs are narrow interfaces or callbacks defined by the consuming domain and wired in the composition root (`apps/mobile/src/compositionRoot.ts`). Read a factory's deps JSDoc before wiring it. Every HTTP stack gets the diagnostics `upstreamListener` as `onUpstreamCall`.
- `src/legacy-migration`: one-time import of the NativePHP SQLite database on first launch (Laravel `encrypted` casts, per-device APP_KEY read through the attachment bridge). See its `README.md`. The legacy DB is opened read-only and never deleted.

### `@altuu/features`

- One folder per area: `shell` (layout, tabs, session-expiry picker, status banners, What's New, shared helpers such as `TypedWebView`, `openInAppBrowser`, `hostOf`), `services` (query runtime, stores, operation keys), `account`, `courses`, `material`, `discuss`. Each area exports from its `index.ts`.
- Data access goes through `useServiceQuery` / `useServiceMutation` with an `op` key from `services/operations.ts`. The key drives diagnostics and the short error code shown to users ("載入課程失敗 [CRS-U500]"); add a key when a new kind of call appears. Query keys: keep the first element unique per area; share keys when two areas read the same data (`courseKeys.list`, `discussQueryKeys.boards`) so invalidation reaches both.
- Route files in `apps/mobile/src/app` stay thin: they import a screen from `@altuu/features`.
- Port legacy behaviour faithfully (layout, copy, loading skeletons, empty, error/retry, pull-to-refresh). Dark mode via `dark:` classes. Respect safe areas.
- Interactive elements that e2e flows use carry a `testID` (see `apps/mobile/e2e/README.md`). Keep them when refactoring.

### `@altuu/ui`

NativeWind preset (`tailwind-preset.js`, Tailwind 3 / NativeWind 4, not Tailwind 4), theme provider and accent palettes (oklch pre-converted to hex: React Native has no oklch), base components (`Screen`, `PageHeader`, `TransparentPageHeader`, `BackButton`, `Button`, `Sheet`, `ConfirmDialog`, `ToggleSwitch`, `Text`, `ErrorRetryView`) and the `Icon` component. `Icon` draws Heroicons v2 outline paths (`icons/paths.ts`) and, with `solid`, the filled variants in `solidIconPaths`. Add new icons there instead of local SVG wrappers. Promote a component here once a second area needs it.

### `@altuu/attachment-bridge` (`modules/attachment-bridge`)

The only custom native module (Swift + Kotlin):

- `setWebViewCookies(url, cookies)` / `clearWebViewCookies()`: writes into `WKWebsiteDataStore.default().httpCookieStore` / Android `CookieManager`.
- `download({ url, headers, cookies, fileName })` with progress events: URLSession / OkHttp with explicit cookies, no shared jar. Files land in `<cache>/attachments/<id>/`.
- `previewFile(uri, mimeType)` (QuickLook / `ACTION_VIEW`) and `saveFile(uri, fileName, mimeType)` (document picker / `ACTION_CREATE_DOCUMENT`).
- Legacy NativePHP access for the data migration (per-device APP_KEY, file existence).

In Jest, mock it with `jest.mock('@altuu/attachment-bridge', () => require('@altuu/attachment-bridge/mock'))`. Changes to the native code need a device build by the user.

### WebView rules (`react-native-webview`)

- **Never** set `sharedCookiesEnabled`, `incognito` or `cacheEnabled={false}`: on iOS they switch to a non-persistent data store that ignores the seeded cookies.
- Seed the HUNGU / school portal session with `setWebViewCookies` before loading an authenticated URL (material HTML, in-app browser, image lightbox).
- Use `TypedWebView` from `packages/features/src/shell/TypedWebView.ts` (react-native-webview's own prop types collapse to `never` under strict TS).

## Commands

Run from the repository root unless noted.

| Task                     | Command                                                                      |
| ------------------------ | ---------------------------------------------------------------------------- |
| Install                  | `npm ci` (workspace deps: `npm install <pkg> -w <workspace>`)                |
| Lint                     | `npm run lint` (`npx eslint <paths>` for a subset)                           |
| Format                   | `npm run format` / `npm run format:check`                                    |
| Typecheck                | `npm run typecheck` (`npm run typecheck -w @altuu/features` for one package) |
| Tests                    | `npm test` (all workspaces) or `npm test -w @altuu/core`                     |
| Bundle check (no device) | from `apps/mobile`: `npx expo export --platform ios --output-dir <tmp dir>`  |
| Project health           | from `apps/mobile`: `npx expo-doctor`                                        |
| Native deps              | from `apps/mobile`: `npx expo install <pkg>` (picks SDK-compatible versions) |
| Regenerate DB migrations | `npm run db:generate -w @altuu/core`                                         |

**Device builds are run by the user, never by agents**: `npx expo run:ios`, `npx expo run:android`, `expo prebuild`, xcodebuild, gradle and fastlane. When a change needs one (native module, config plugin, new native dependency), say so and list what to check on device.

## Testing conventions

Every change ships with tests. Run the smallest relevant set first, then the whole workspace.

- **Core: Vitest** (`packages/core`, `src/**/*.test.ts`). Parsers and actions are tested for **parity** with the legacy PHP app against `packages/core/test/fixtures` (index: its `README.md`). Use `loadFixture` for inputs, `loadExpected` for asserted values and `loadGolden` for full-output parity: the output must deep-equal the golden `output`, except documented intentional differences such as material-proxy URLs. Do not edit fixtures; if one looks wrong, report it. Some generators (`__generators__`, `__vectors__`, `__fixtures__/*.php`) need the legacy app (see `tools/legacy-fixtures-gen/README.md`). `src/http/testing.ts` provides `createFakeFetch` and an in-memory session store.
- **Features: jest-expo + React Native Testing Library** (`packages/features`). RNTL 14's `render` is async (`await render(...)`). Use the fakes in `src/testing/fakeServices.ts` (`createFakeServices`, `createTestQueryClient`, `resetStores`) and per-area helpers (`account/testing.tsx`, `courses/testUtils.tsx`). Always create query clients with `createTestQueryClient()`: it disables gc timers so Jest exits without `--forceExit`.
- **Attachment bridge: Jest** with the JS mock of the native module.
- **E2E: Maestro** flows in `apps/mobile/e2e` (login, switch account, course + material, discuss thread, session expiry). They need real credentials from `MAESTRO_*` env vars and a simulator; see `apps/mobile/e2e/README.md`. Agents can only validate their YAML.
- Styling-only changes: verify with lint, typecheck and a bundle export; no new tests are needed for colours alone.

## Release pipeline

`.github/workflows/mobile-release.yml` + `.github/actions/setup-expo-build`: version from the tag, `expo prebuild`, then fastlane in `apps/mobile/fastlane` (iOS archive + App Store Connect upload, Android AAB to the Play internal track, sideload APK with its own keystore and a build-provenance attestation). RC / beta builds set `EXPO_PUBLIC_MATERIAL_SOURCE_VIEWER_ENABLED`. Secrets, lanes and the dry-run checklist are in `apps/mobile/fastlane/README.md`. CI also runs `lint.yml` (format, lint, typecheck) and `tests.yml` (`npm test`).

## Code style

- TypeScript strict, 2-space indent, single quotes, trailing commas (Prettier). Descriptive names (`isSubscriptionActive`, not `sub()`).
- Small focused modules. JSDoc only where the why is not obvious; reference the legacy name being ported when it helps (`legacy restoreActiveMediaRoute`).
- Reuse before writing: check `@altuu/ui`, `packages/features/src/shell` and sibling areas for an existing component or helper.
- Conventional Commits (`feat(material): ...`), enforced by commitlint. lint-staged runs Prettier and ESLint on commit.
- Do not add dependencies casually; prefer what Expo SDK 58 and the existing packages provide. Native dependencies need `npx expo install` and a device build.
